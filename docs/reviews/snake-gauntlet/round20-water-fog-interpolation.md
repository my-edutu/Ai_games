## Production experiment and safeguards

The same animated opaque 256×256 authored water palette, one filtered color fetch, UV flow, reduced-motion freeze, fog-color blend, broad lake coverage and all original live foam/falls remain. The original fog smoothstep moves from each water fragment to the vertex shader and interpolates over a 64×64 subdivided 512-unit plane. Fog near/far use the existing scene uniforms; no silhouettes, food, portals, hazards or water surfaces are hidden. This is a real geometry-vs-fragment trade: water triangles rise by 8,190 relative to the original two-triangle plane. No game simulation, AI, scoring, public snapshot authority, HUD, captions, accessibility, fallback, recovery or release threshold changes. No copied or paid assets. The mathematical 8-unit depth interpolation bound in a 48–110-unit linear fog interval is below 0.013 fog factor; this is a model, **not** a replacement for the captured WebGL comparison.

Regression work: existing water tests now check original fog factor/color continuity instead of requiring the specific obsolete THREE shader chunk, retaining one texture fetch, resource bounds, flow and frozen reduced motion. Two new focused tests cover geometry bound after Three's lazy bounding-sphere computation, shader stage, resources, reduced motion and the interpolation envelope. [First general CI run 41184331800](https://github.com/my-edutu/Ai_games/actions/runs/41184331800) had **547/548** Node tests because the new test wrongly assumed a PlaneGeometry bounding sphere had already been computed before a render; production was not at fault. The corrected test calls `computeBoundingSphere()`. The unchanged new shader had already passed real browser drawing in that first run.
