# Round 47 — authoritative-visual minimap repaint boundaries

Date: November 1, 2026. Fixed bar: official *Snake Pass* in-game/character/world screenshots and motion; *ASTRO BOT* secondary craft, no imported licensed assets. Builds on R46, not a redo of its source-controlled one-pass WebGL work.

## Exact regression and smallest unmet slice

The 2D whole-garden minimap is visible during follow/detail camera modes and re-renders on **every** `/snapshot` HTTP poll, including duplicate immutable game frames. Its canvas clears, re-strokes every stone obstacle, portal, hazard, body cell and fruit, and re-inflates the desktop/mobile compositor. The empty minimap button also starts unhidden before first public frame. This is unnecessary offscreen/composition work, not a cause proven for the default overview's strict frame starvation.

The public `revision` is chiefly movement-based; **hazard activity can change on a tick without movement**. A naive `(runToken, revision)` paint gate would hide a trap transition. The chosen repaint signature includes exactly the visible public cues: run token, revision, dimensions, snake cells, obstacle cells, hazard **active** flags, portal ends and fruit cell. It intentionally excludes hazard **phase**, timestamps and other invisible fields. This allows safe identical-frame suppression without losing danger, fruit, teleport or occupancy changes; first visibility and re-entry always repaint.

## Production change and boundaries

Only `public/snake-stream/overview.mjs` changes production: initially hide unpopulated minimap, compute a cheap immutable-public visual signature while visible, skip 2D paints when unchanged, and invalidate by returning from hidden. No Three.js scene, shader, texture, mesh, renderer submission gate, AI, seeded simulation, scoring, public schema, audio, HUD caption, camera physics, portal discontinuity, reduced-motion, fallback, network polling or recovery changes. No new GPU resources; one bounded string cache in UI only. The algorithm is intentionally conservative: any change to a visible cell causes a complete repaint. Complexity of the signature is O(current visible map objects) per poll, but saves drawing the same content on identical polls.
