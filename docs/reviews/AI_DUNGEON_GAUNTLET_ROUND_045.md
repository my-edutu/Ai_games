## Proven defect and smallest independently verifiable increment

Round 43's actual software-WebGL Chromium trace had exhibited approximately 13 seconds with stale spectator updates while authoritative gameplay advanced; R44 avoided eagerly constructing optional bloom on recognized CPU rasterizers. Source inspection uncovered a separate lifecycle hole in `public/ai-dungeon/boot-watchdog.js`: the `webglcontextlost` handler did not cancel the event (required for WebGL restoration), and the startup timer could overwrite `context-lost` or `recovering` with `ready` using frames captured **before** restoration. `public/ai-dungeon/app.js` also hid the recovery panel on each valid authoritative state update, even when 3D rendering was unavailable. Therefore a continuing autonomous simulation could conceal a broken spectator output.

Small fixes, no new game assets: the loss handler now calls `preventDefault()`; a pending restore holds the visible recovery status until the actual renderer's diagnostic frame counter changes; the healthy render loop clears that status; and live state polling no longer dismisses a known graphics failure. An already-started watchdog can recover after restoration. Renderer frame-counter reset is accepted as change rather than assuming strictly increasing values. Failure, stall and fresh-frame states remain separate from authoritative gameplay truth.
