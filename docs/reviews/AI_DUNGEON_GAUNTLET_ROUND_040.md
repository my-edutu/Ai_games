## Final grounding correction — actual RED → GREEN evidence

Inspection of the original 3D mesh contract exposed a subtle real visual defect after the first pass: `new THREE.DodecahedronGeometry(.5,1)` has **vertical geometry bounds -0.5…+0.5**, while the planner centres each rock at `height/2-.18`. That combination raises the rock bottom to about `height/4-.18`, **hovering over the floor**. This is precisely the kind of attractive-sounding but false 3D improvement that a harsh critic must reject.

A fourth new test was written to prove that the actual renderer uses **unit-radius geometry with centre = height/2-.18**, so that the ground contact is -0.18m. Its first local run against `4e5cbb2` **failed exactly as intended**: **6 passed / 1 failed** on the missing geometry contract. The RED output is retained in the local review workspace. [Test-only commit 6aca679](https://github.com/my-edutu/Ai_games/commit/6aca67967738c346f82956e067b5f1c811e0c7ff) preceded the renderer fix. [Code fix cb5b4e5](https://github.com/my-edutu/Ai_games/commit/cb5b4e5f90908f299460cd9301874fa7daf2cb52) changes the actual mesh to `new THREE.DodecahedronGeometry(1,1)`; the same focused seven tests now pass. A further test-only clarification [c6c030a](https://github.com/my-edutu/Ai_games/commit/c6c030a6b5b5a07be2935bd282f6810005bcc177) audits **full rotated unit-radius physical bounds**, instead of the earlier optimistic half-width clearance. The corrected planner still keeps every rock outside the map corners plus 2m.
