## 1. Contact-gated weight transfer on real imported GLB legs

The previous Round 42 elbows moved but melee weight transfer still looked like swimming in place. Tests were authored first in [`1c9a56f`](https://github.com/my-edutu/Ai_games/commit/1c9a56f5c) and a real Chromium test in [`9e2595e`](https://github.com/my-edutu/Ai_games/commit/9e2595e2b). [`2d5ad45`](https://github.com/my-edutu/Ai_games/commit/2d5ad4592) added a pure `planRigContactBrace` for genuine adjacent melee attack states; [`2d8754b`](https://github.com/my-edutu/Ai_games/commit/2d8754bc4) layered bounded wind-up/drive/recovery onto the already imported thigh, calf and ankle bones in `model-assets.js`. Bracing is permitted only when `planCombatFacing` verifies one-cell, same-row/column, unobstructed contact from an immutable public snapshot; never from guessed proximity. The planner rejects off-lane, out-of-range, nonmelee, missing, invalid and reduced-motion cases, and returns to neutral without cumulative deformation. Existing AnimationMixer playback is unchanged. There is no new skeletal asset or collision change.

The genuine Chromium `dungeon-authored-motion.spec.cjs` selected a seeded `DungeonRuntime.step` attack transition rather than hand-making a winning combat event. The [real 1440×832 braced-leg screenshot is in artifact 13061615875](https://github.com/my-edutu/Ai_games/actions/runs/41251140585/artifacts/13061615875). The true capture was opened and examined. Its surrounding wall mass remains rectangular and the melee fighters visually overlap; the 0.19 rad cap and positive runtime diagnostics prove a narrow rig motion, **not** realistic planted-foot weight or clear weapon contact. Exact-code browser shard 1 in run 41251140585 passed **20/20**, including the real brace assertion; shard 3 passed **19/19**.

## 2. Diagnose real Chromium stall; protect optional visual effects

The original complete [browser run 41251140585](https://github.com/my-edutu/Ai_games/actions/runs/41251140585) was **RED: 59/60 Chromium tests** (shard 2: 19/20) despite clean simulation authority. A real failing [Playwright trace/video, artifact 13061083943](https://github.com/my-edutu/Ai_games/actions/runs/41251140585/artifacts/13061083943) was inspected. The trace contains real `/dungeon/state` HTTP snapshots advancing from run 4/tick 125 to run 5/tick 34–35, but a roughly **13-second gap in state polling** and then fewer than three client-observed ticks within the existing 20-second window. The backend had progressed, so this is *not* a simulation deadlock; the saturated browser can nevertheless freeze spectator updates. The browser failure is real and must not be called flaky green or waived.

New tests were committed first at [`1490999`](https://github.com/my-edutu/Ai_games/commit/1490999784721806ea29c4552e7c737d997e8a80), and the exact authority job `124688527296` on [test-first CI run 41252428904](https://github.com/my-edutu/Ai_games/actions/runs/41252428904) recorded **two expected RED failures**: missing `postFXStallAction` and missing actual WebGL fallback wiring. [`c98ee2e`](https://github.com/my-edutu/Ai_games/commit/c98ee2eb63742d35efd207fcdf1b1b84fa6b2309) adds a pure, finite, bounded planner to skip **optional bloom** after either a single measured compositor frame >=2500 ms or two consecutive frames >650 ms. Fast GPUs retain glow. It changes the actual Three.js scene to direct rendering, updates the Glow control/diagnostics honestly, and does not auto-oscillate between quality modes. A spectator may explicitly re-enable glow. The renderer and scene continue; deterministic AI, saves, combat, game ticks, provider state and replay do not read the measurement. This *cannot* yet be called a verified p95 or soak improvement: an initial large stall can still occur, and switching to direct rendering does not guarantee all slower GPUs meet frame budgets.

## Independent spec and quality critique

**Spec:** New GLB bracing consumes read-only snapshots; compositor adaptation consumes only presentation wall time. No authority mutation, RNG draw, hit timing, save/schema change, output content, new third-party asset or external service. Existing reduced-motion neutral remains. One-shot gesture stages are bounded and reversible; per-actor joint count does not change. Bloom must not be described as active when bypassed.

**Harsh quality:** The actual real-play capture still looks boxy and small at spectator distance. A slight lower-body rotation is not a physically solved stance, and exact weapon impact attribution remains ambiguous. The GPU fallback reacts *after* a slow render; catastrophic one-frame freezes may remain, particularly in software rendering. Review was author-led; the connected coding/subagent tunnel was unavailable, and no independent reviewer or ultracode agent executed. No blind A/B aesthetic win is claimed.
