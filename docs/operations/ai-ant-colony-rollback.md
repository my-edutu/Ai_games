# AI Ant Colony / Ecosystem — Rollback Plan

## Trigger conditions

Rollback is mandatory for any replay divergence, duplicate effect application, private authority exposure, unauthorized operator action, corrupt record evidence, incompatible snapshot accepted as valid, repeated restore failure, stale-writer split brain, unresolved unsafe public output, platform-policy breach, failed endurance integrity, canary rollback verdict, or open P0/P1.

## Immutable rollback identity

The release manifest owns the rollback source SHA, deployment artifact, configuration hash, content hash, and fresh-run boundary. Operators must not substitute a branch name, abbreviated SHA, mutable tag, latest image, or unreviewed configuration. The rollback candidate must pass health, compatibility, and output checks before public resumption.

## Procedure

1. Disable audience interaction and public text.
2. Switch capture to the intentional safe scene.
3. Record current candidate SHA, manifest checksum, run ID, lease generation, command sequence, snapshot ID, state checksum, public scene, and incident trigger.
4. Fence the active writer. Confirm no worker can renew the old lease.
5. Stop or isolate the failed deployment.
6. Deploy the manifest rollback artifact and its exact configuration/content hashes.
7. Start at a fresh-run boundary unless a snapshot is explicitly compatible with the rollback deterministic version, config hash, and content hash.
8. When compatible restore is permitted, select the newest valid rollback-compatible snapshot, replay contiguous commands, and verify the final checksum.
9. Verify health endpoints, autonomous tick progress, snapshot progress, moving non-black output, correct scene, captions, audio policy, queue bounds, memory slope, and private-control separation.
10. Resume public output first. Resume interaction only after provider, moderation, entitlement, audit, and persistence health are verified.
11. Open a new canary record. Material rollback resets endurance/canary and invalidates evidence tied to the replaced candidate.

## Failure handling

If rollback restore diverges, has sequence gaps, or lacks compatible evidence, quarantine and start a fresh deterministic run. Never edit stored evidence to make a checksum pass. Never copy applied influence IDs or records manually. Never treat an incident-generated halt or intermission as a game result or record.

## Evidence and review

The rollback packet requires owner, independent witness, timestamps, trigger, old/new candidate identities, hashes, deployment logs, lease fencing proof, snapshot/replay range, before/after checksums, screenshots/capture samples, output verification, interaction status, and accepted risks. Security reviews privacy or credential incidents. Release ownership approves re-promotion. Product reviews viewer disclosure when the public run was interrupted.
