## Observable defect and bounded fix

[Previously completed genuine Chrome run 43335645463](https://github.com/my-edutu/Ai_games/actions/runs/43335645463) passed five of six browser trials, but strict real HP impact presentation failed `AUTHENTIC_DAMAGE_NOT_VISUALLY_ADMITTED`. It also reported multi-second real WebGL stalls (including legacy), so do not assign those whole-system stalls to D04. A separate, reproducible D04-only correctness defect was found while reviewing this failure: `advance()` refreshed the wall clock *before* D04's retained visual pass, then `popDue()` used that earlier age. When visual processing itself took the last part of an injury's 400ms lifetime, the controller could admit old HP fragments after the actual deadline, only for post-WebGL audio to correctly reject them as stale.

[Regression-first commit 73168ba](https://github.com/my-edutu/Ai_games/commit/73168bab2b021aba15bd0f587d22886aa0338604): injected independent monotonic clock and costly retained-visual pass. A real HP decline was 350ms old at visual-pass start, and the visual adapter consumed another 120ms; the pre-fix controller incorrectly emitted a shard at 470ms. [Red CI 43342835119](https://github.com/my-edutu/Ai_games/actions/runs/43342835119) observed **233/234 native contracts passing**, with the new regression failing as expected (expected zero visual admissions, actually one).

[Correction commit 0282040](https://github.com/my-edutu/Ai_games/commit/0282040ea7a1d7c33b2e62be2ceafa2d29e6c7cb): calculate pending cue age from the maximum of (1) the existing raw-frame age and (2) a validated elapsed real time between that exact public observation and the **already sampled end-of-visual-pass clock**. The same effective age controls both the <=400ms visual admission deadline and deferred presentation timing. No new render loop or clock read was added. In the current clock-bound submitted-frame path, a late authentic HP fragment now fails closed **before** the WebGL attempt; a fresh 230ms injury still obtains the first eligible visual frame and waits for genuine post-render acknowledgement to authorize original foley. A null, regressed or unavailable wall clock retains the previous conservative raw interval fallback.

For `expired-pending-before-frame` terminal receipts only, reuse existing start/end-visual clocks to record `pendingExpiredBeforeVisualMs`, `pendingExpiredVisualPassMs` and `pendingExpiredWallAgeMs`. These are JavaScript observation/visual-phase timings, not GPU submission, video PTS, perceptual sound onset or causal attribution. Invalid phase stamps remain null. All receipts retain `frameId:null`, `audio:false`, `submittedClockMs:null` and `sampleSynchronized:false` when no frame was submitted. The complete receipt history remains capped at 64.
