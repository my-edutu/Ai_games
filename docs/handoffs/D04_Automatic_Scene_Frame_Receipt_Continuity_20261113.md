## Defect and genuine-submission boundary

Current Dungeon `public/ai-dungeon/app.js` increments `d04PresentedFrameSerial` after each real WebGL render, independently of floor/run changes. Yet D04 `flush('scene-transition')` reset both `highestNumericPresentedFrame` and the bounded string receipt-ID set. If a previously acknowledged frame ID was replayed during a new floor/run with a pending original sound, the controller wrongly treated that old receipt as a fresh WebGL submission and allowed the new sound. This is a deterministic controller correctness defect; **we have not measured it occurring in captured genuine browser playback**. The source-level issue is independent of the intermittent multi-second browser stalls.

Automatic authority transitions now preserve `lastPresentedFrame`, `highestNumericPresentedFrame`, and the bounded 64-entry opaque-ID set while still flushing old pending cues, old audio and visual instances, and old cue-observation clocks. This makes a pre-transition frame ID ineligible to certify sound from a new floor/run. Explicit `reset()` and `dispose()` continue to discard receipt history, allowing a deliberately reset renderer to restart a numeric sequence. No new effect pool, state trajectory, audio voice, draw call or unbounded history is introduced.
