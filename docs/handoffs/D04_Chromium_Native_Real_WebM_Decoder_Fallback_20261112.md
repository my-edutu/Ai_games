## Implemented, isolated improvement

- Add a **read-only Chromium-native decoding fallback**, `sampleChromiumDecodedD04WebM` in `tests/browser/dungeon-d04-decoded-video-proof.cjs`, operating on the unchanged, already recorded, same-window **real WebGL receipt-readback + opted-in original soundstage WebM**. This fallback does **not** render into the game canvas or produce substitute combat footage.
- Gate input to exact real-WebGL readback source, recorded status, one video and one audio track, confirmed opt-in/live soundstage, bounded encoded bytes (4 MiB), and finite metadata (16–4096px, 0.2–30s). A hidden muted browser `<video>` decodes the original immutable WebM, seeks at four bounded positions, and samples 24×16 RGB pictures into a short FNV hash and luma range. The decoder always removes its element and revokes its object URL; malformed, unsupported or timed-out decode fails closed.
- Add pure `classifyChromiumDecodedRealWebM`: two to four monotonic genuine decode samples with validated dimensions, timestamps, hashes and non-flat pixels can distinguish distinct image samples from static/sparse ones. It returns only `BROWSER_DECODED_MOVING_PIXELS_UNALIGNED`, `BROWSER_DECODED_STATIC_OR_SPARSE_UNALIGNED`, or `BROWSER_DECODE_UNVERIFIED`. Every result has `sampleSynchronized:false`. Distinct seek samples are **not** a count of actual VP8 frames, not video presentation timestamps, not evidence of blade-tip contact, and not confirmation that combat foley reached encoded audio.
