# Phase 0 — Eko Run Constitution and Research Pack

**Game:** Eko Run (`eko-street-run`)  
**Purpose:** Establish an executable, original, culturally grounded and technically coherent game contract before runtime implementation.  
**Status:** `in-review`  
**Owning phase:** 0  
**Last material review:** 2026-09-15  
**Phase ID:** `EKO-P00`

## Viewer-Visible Outcome

No playable build is promised in Phase 0. The outcome is that a future implementer can build Eko Run without guessing its goal, identity, rules, architecture, asset policy, testing model or stop-ship conditions.

## Scope

- complete required catalogue game documents;
- Lagos/Nigerian visual reference constitution;
- stock/reference asset provenance and rights policy;
- original-IP boundary;
- stable PRD requirements and traceability;
- Phase 1 architecture/test contracts.

## Non-Scope

Runtime simulation, renderer, controls, AI, audio playback, viewer integration and downloadable release assets.

## Prerequisites

Root `AGENTS.md`, Eko `AGENTS.md`, `docs/EKO_EXPERIENCE_STANDARD.md`, catalogue documentation/architecture/production standards and all 22 specialist skills.

## Requirements Addressed

`NFR-UX-002`, `NFR-ASSET-001` current-reference subset, and planning/traceability ownership for all Phase 1 requirements.

## Workstreams

1. product/creative/progression constitution;
2. Lagos/reference and asset-rights pack;
3. audiovisual/cultural identity constitution;
4. AI/viewer/economy/security/reliability future boundaries;
5. deterministic technical architecture and testing contract;
6. requirement traceability and review evidence.

## Static Verification

`tests/foundation/eko-run-docs.test.cjs` verifies required documents, core terms and prohibited placeholder scan. Manual review checks semantic consistency and rights/identity decisions that static tests cannot prove.

## Accessibility / Safety / Security

Phase 0 must specify multimodal critical cues, reduced motion/flash, non-graphic neutral crowd/fight incidents, no stock-person negative depiction, original fictional brands/signage, privacy minimization and provider separation.

## Acceptance Criteria

- every required game document exists;
- no prohibited placeholder language remains in Eko game docs;
- PRD requirements have stable IDs and traceability;
- a reviewer can state the protagonist, goal/progress, immediate adversarial pressure and Lagos identity without mentioning Mario;
- game design and experience standard both require excellent mechanics without theme and recognizable identity without title;
- external references are recorded and default to reference-only with third-party-rights review;
- technical architecture locks fixed-step authority and presentation separation for Phase 1;
- no document claims runtime evidence that does not exist.

## Evidence Bundle

`evidence/eko-run/phase0/PHASE-00-REVIEW.md` plus successful `eko-run-docs.test.cjs` on the candidate commit.

## Stop-Ship Findings

Contradictory system ownership, copied franchise asset direction, unreviewed runtime stock-person usage, missing requirement owner/evidence, provider/render mutation of authority, or placeholder requirements block Phase 0 exit.

## Rollback

Phase 0 is documentation-only. Revert the phase commit(s) if review finds irreconcilable contradictions; no runtime migration/data action is required.

## Exit / Handoff

After the Phase 0 candidate commit passes static and semantic review, Phase 1 may implement only the approved foundation contracts. Later design changes that alter deterministic ownership require architecture/version review.
