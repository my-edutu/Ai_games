# Phase 3 — Broadcast Experience

**Target:** R2 streamed vertical slice  
**Software status:** IMPLEMENTED — verification is attached to the active completion PR  
**Release status:** R2 only; this phase does not establish production readiness

## Objective

Turn the deterministic Phase 2 simulation into a legible, privacy-safe, resilient livestream product without allowing presentation timing, browser code, audio, or polling to mutate authoritative gameplay.

## Delivered contract

- Immutable `ZombieRenderSnapshot` projection with a public checksum and no seed, run ID, config, world internals, event log, provider identifiers, or hidden AI state.
- Dedicated Canvas broadcast host with preparation, horde, intermission, result, and recovery scenes.
- Hierarchical HUD for day, objective, base integrity, survivors, resources, horde pressure, current AI intent, captions, and audience-influence status.
- Responsive layouts validated at 1920×1080, 1280×720, 844×390, and 640×360; all four survivors and five supply classes remain visible at the smallest supported feed.
- Clean-feed, reduced-motion, high-contrast, local mute, and caption-preserving modes.
- Bounded semantic Web Audio: no text-to-speech, no unbounded voice/node growth, deterministic event deduplication, and captions that remain available while muted.
- Serialized state polling, bounded replay frames, stale/divergent snapshot rejection, run-boundary cleanup, and safe-scene recovery from the latest valid public snapshot.
- Stream host health endpoint and self-test covering assets, privacy, restart continuity, presentation recovery, and authority isolation.
- Chromium capture evidence generated by CI under `artifacts/zombie-phase3`.
